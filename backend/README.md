## Comprobantes internos de pago

El módulo `receipts` registra comprobantes internos después de confirmar operaciones
de Wompi:

La variable `FACTURA_ELECTRONICA=FALSE` mantiene el sistema en modo de desarrollo:
los documentos generados son comprobantes internos y no DTE fiscales. Cambiarla a
`TRUE` no basta para emitir facturas válidas; primero debe implementarse y
configurarse la integración autorizada con Hacienda o un proveedor de DTE.

La preparación del módulo [`dte`](./src/dte) incorpora las entidades para cabecera,
detalle y contingencias, junto con la configuración del ambiente de pruebas del
firmador y del Ministerio de Hacienda. Mientras `DTE_MODE=development`, no se firman ni transmiten documentos y no se
realizan llamadas a esos servicios. En ese modo, los payouts generan un DTE simulado
con ambiente `00`, estado
`BORRADOR` y prefijo `DTE-DEV-` para probar el flujo y el correo sin llaves
oficiales. Este documento no tiene validez fiscal. Para emitir documentos
oficiales, configura `DTE_MODE=production`, `FACTURA_ELECTRONICA=TRUE` y la
integración real con el firmador y Hacienda.

- `credits_top_up`: recargas de créditos.
- `escrow_funding`: fondeo de contratos en custodia.
- `platform_commission`: comisión incluida en el fondeo.
- `influencer_payout`: dispersión aprobada al influencer.

En `FORMA_PAGO=desarrollo`, la dispersión al influencer se simula aunque no
exista una cuenta bancaria registrada. Se genera una transacción de desarrollo
(`dev-payout-*`), el comprobante, el DTE simulado y el correo de notificación.
En `FORMA_PAGO=produccion`, Wompi exige una cuenta bancaria válida y la
dispersión real no se ejecuta sin ella.

Los comprobantes se consultan con `GET /api/receipts` y
`GET /api/receipts/:id`, autenticados con JWT. Estos documentos son informativos,
no son DTE ni sustituyen una factura electrónica autorizada por el Ministerio de
Hacienda de El Salvador. Después de una dispersión confirmada por Wompi, el
comprobante del payout se envía al correo del influencer cuando SMTP está
configurado. La integración fiscal requerirá posteriormente datos del emisor,
certificado/firma, autorización y un proveedor o API oficial de DTE.

## Project setup

```bash
$ npm install
```

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

## Run tests

```bash
# unit tests
$ npm run test

# e2e tests
$ npm run test:e2e

# test coverage
$ npm run test:cov
```

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.
